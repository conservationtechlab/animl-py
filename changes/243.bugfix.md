# Fix NaN handling in get_animals and get_empty functions

## Changes
- Modified `get_animals()` function to remove rows with NaN values in the 'category' column before filtering for animal detections
- Modified `get_empty()` function to remove rows with NaN values in the 'category' column before filtering for non-animal detections
- Added comprehensive test suite (`tests/split_test.py`) covering NaN handling scenarios:
  - No NaN values
  - With NaN values
  - All NaN values
  - Mixed scenarios
  - Prediction mapping verification
  - Confidence value handling

## Rationale
Previously, NaN values in the 'category' column could cause unexpected behavior when converting to int and comparing. Now both functions explicitly remove rows with NaN in the 'category' column before processing, ensuring clean data and preventing errors.

## Impact
- Data quality improvement: NaN rows are now cleanly excluded rather than potentially causing conversion errors
- Backwards compatible: Functions still return the same structure, just with guaranteed NaN-free results
- Addresses issue #243
